# Infinite Tale Weaver

Infinite Tale Weaver is a full-stack, AI-powered choose-your-own-adventure app. Players build a world and protagonist, then continue an open-ended story whose characters, inventory, quests, artwork, and consequences persist between sessions.

This edition is designed for a GitHub → Google AI Studio workflow. Supabase and Lovable runtime dependencies have been removed. Authentication, saves, events, and generated media now use Firebase.

## Highlights

- Three-step Story Builder with custom genres, tones, art styles, character details, sports stories, danger modes, and AI/media controls
- Firebase Google sign-in, private Firestore saves, and Firebase Storage media
- Lightweight story library with rename, setup duplication, JSON export, and deletion
- Gemini 3.6 Flash storytelling with structured state updates
- Nano Banana 2 scene artwork, Gemini TTS narration, Gemini Live character conversations, and optional Gemini Omni video scenes
- Responsive play screen, mobile journal, keyboard shortcuts, reduced-motion support, and editable in-story settings
- Server-only AI keys, verified Firebase ID tokens, owner-only security rules, and daily AI usage limits

## Technology

- React 19, TypeScript, TanStack Start, TanStack Router, and TanStack Query
- Vite 8, Nitro, Tailwind CSS 4, Radix UI, and shadcn-style components
- Firebase Authentication, Cloud Firestore, Firebase Storage, and Firebase Admin
- Gemini API through server functions; no Gemini key is shipped to the browser

## Quick start

Requirements:

- Node.js 20.19 or newer
- A Firebase project
- A Gemini API key from [Google AI Studio](https://aistudio.google.com/apikey)

Install and start the app:

```bash
npm install
cp .env.example .env
npm run dev
```

On PowerShell, use `Copy-Item .env.example .env` instead of `cp`.

The development site is normally available at `http://localhost:3000`.

## 1. Configure Firebase

In the [Firebase console](https://console.firebase.google.com/):

1. Create or select a project.
2. Add a Web app under Project settings.
3. Enable Authentication → Sign-in method → Google.
4. Create a Cloud Firestore database in Native mode.
5. Create a Firebase Storage bucket.
6. Add `localhost` and every deployed domain to Authentication → Settings → Authorized domains.
7. Copy the Web app configuration values into the `VITE_FIREBASE_*` entries in `.env`.

The Firebase Web configuration is not a server secret. Access is protected by Authentication plus the included Firestore and Storage rules.

Deploy the included rules and indexes from the repository root:

```bash
npx firebase-tools login
npx firebase-tools use YOUR_FIREBASE_PROJECT_ID
npx firebase-tools deploy --only firestore:rules,firestore:indexes,storage
```

Do not deploy in production before deploying these rules. They enforce owner-only reads and writes for every adventure and media object.

## 2. Configure server credentials

Set these required values in `.env` for local development, and as environment variables/secrets in the deployed runtime:

```dotenv
GEMINI_API_KEY=your-server-only-gemini-key
FIREBASE_PROJECT_ID=your-project-id
FIREBASE_STORAGE_BUCKET=your-project.firebasestorage.app
```

Firebase Admin uses Application Default Credentials. For local development, the recommended option is:

```bash
gcloud auth application-default login
```

If Application Default Credentials are unavailable, set `FIREBASE_SERVICE_ACCOUNT_JSON` to a one-line service-account JSON value. Treat it as a secret and never commit it. A Google-hosted runtime can instead use its attached service account; give that account only the Firestore, Storage, and Firebase Authentication user-lookup access this app needs.

## 3. Import through GitHub into Google AI Studio

1. Extract this project so `package.json` is at the repository root.
2. Commit the project to a new GitHub repository. Do not commit `.env`.
3. Import the GitHub repository into Google AI Studio.
4. Connect/select the same Firebase project used above.
5. Add `GEMINI_API_KEY` as a server secret.
6. Add the `VITE_FIREBASE_*`, `FIREBASE_PROJECT_ID`, and `FIREBASE_STORAGE_BUCKET` environment values from `.env.example`.
7. If the runtime is not using an attached Google service account, add `FIREBASE_SERVICE_ACCOUNT_JSON` as a server secret.
8. Use `npm run build` as the build command and `npm start` as the production command when the host asks for them.
9. Add the deployed hostname to Firebase Authentication's authorized domains.

The production server entry is `.output/server/index.mjs`, generated by `npm run build`.

## Firebase data layout

```text
adventures/{adventureId}                 lightweight library metadata
  state/current                          world, inventory, quests, settings
  scenes/{sceneId}                       ordered narration and media references
  events/{eventId}                       pending/resolved fate events
users/{userId}/usage/{YYYY-MM-DD}        server-managed AI usage counters

Storage:
users/{userId}/adventures/{id}/scenes/{sceneId}
```

Library queries load metadata only. The full state and ordered scene history are reconstructed when a story is opened, which keeps the dashboard fast as stories grow.

## Security and operating notes

- AI calls require a verified Firebase bearer token and run on the server.
- Firestore and Storage rules restrict data to the owning Firebase user.
- Stored media uses Firebase's tokenized download URLs. Treat exported or copied media links as bearer links: anyone who receives one can open that individual asset.
- Save deletion removes its Firestore scene/event documents and generated media.
- Video generation uses the preview Gemini Omni Flash model and may not be available in every region or quota tier. Keep video disabled if the project does not have access.
- Generated images and videos can incur significant API and Storage costs. Adjust the `AI_DAILY_*_LIMIT` values for your budget.
- Firebase Web keys belong in `VITE_*` variables; Gemini and service-account credentials never do.
- This rebuild intentionally starts with a new Firebase data store. It does not migrate old Supabase saves.

At packaging time, `npm audit --omit=dev` reports no high or critical advisories. It reports six moderate transitive advisories in Firebase Admin's Google Cloud Storage dependency chain. npm's automated suggestion is an inappropriate Firebase Admin downgrade, so it was not applied; recheck upstream packages during routine maintenance.

## Model defaults

- Story: `gemini-3.6-flash`
- Economy story option: `gemini-3.5-flash-lite`
- Artwork: `gemini-3.1-flash-image` (Nano Banana 2)
- Narration: `gemini-3.1-flash-tts-preview`
- Live character voice: `gemini-3.1-flash-live-preview`
- Video: `gemini-omni-flash-preview`

Preview model names and availability can change. Review the [Gemini models](https://ai.google.dev/gemini-api/docs/models) page before a long-lived production launch.
